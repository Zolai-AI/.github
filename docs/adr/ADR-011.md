# ADR-011: Defer annotation tooling (Label Studio preferred at trigger)

| | |

| Date | 2026-09-29 |
| Decision owner | founder |
| Decision | **DEFER** (needs-founder-decision: annotation volume) |
| Revisit when | First 5+ external annotators → deploy Label Studio, sync exports to DB |

## Context

L1 gold-set annotation (POS, syllables, morphology) is starting under the 60-day
Linguistic Core plan. Today, annotation = **CSV/JSONL files in Git** (e.g.
`data/syllable/gold_human_annotation.jsonl` + `docs/ANNOTATION_GUIDE.md` — noting `data/`
is git-ignored, so gold sets small enough to track live in-repo paths or under `docs/`).
There is no annotation workflow, no annotator accounts, no inter-annotator agreement tooling
(gap G8). Tool landscape verified 2026-09-29: **Label Studio** Apache 2.0 and active
(1.23.0, 2026-03-13; 1.24.0.dev builds Sep 2026); **Argilla** publicly frozen — README
notice 2025-05-16: original authors moved on, no new features/bug fixes planned;
**doccano** MIT (license unverified — secondary source).

## Problem

An annotation platform is only worth its operational cost when **multiple annotators** need
accounts, task assignment, and agreement tracking. With one founder-annotator (and gold
sets measured in hundreds of rows), a tool adds a service, an export-sync job, and UI
maintenance — while files in Git already provide diffing, review-via-PR, and provenance.
But deferral must name the trigger and the preferred tool so the choice isn't relitigated
mid-recruitment.

## Options

1. **Defer; keep CSV/JSONL in Git with review-by-PR** (recommended interim).
2. Deploy Label Studio now.
3. Deploy doccano now.
4. Deploy Argilla now.
5. Build a bespoke annotation UI inside the admin (ADR-009).

## Decision

**DEFER** — annotation tooling is deferred; **needs-founder-decision: annotation
volume/timeline** (UNKNOWN: how many annotators, over what period).
Interim: **CONFIGURE** CSV/JSONL gold sets + annotation guide + PR review.
At trigger (first 5+ external annotators): **ADOPT Label Studio** (**PREFERRED**) and
**INTEGRATE** DB export sync; **doccano** only if strictly text-only needs arise.

## Reasons

- **Tool pays off only with multiple annotators** — with n=1, files beat services
  (complexity: none vs a service + sync).
- **Review-by-PR gives provenance for free** — commits record who reviewed what and when,
  aligning with the human-corrections-auditable constraint.
- **Label Studio is the sanctioned default** — Apache 2.0 (verified) and demonstrably
  active, unlike Argilla (frozen, verified) — so the deferred decision is already made.
- **Volume is UNKNOWN** — committing spend/ops now would guess at the single variable that
  determines ROI; hence explicit needs-founder-decision.

## Consequences

- No annotator accounts, task queues, or IAA metrics in the interim — agreement measurement
  stays manual (acceptable at current scale; note as accepted risk).
- Gold sets must keep strict schema + license/provenance headers so later imports into
  Label Studio are mechanical.
- When Label Studio arrives, an **INTEGRATE** job must sync exports → DB tables
  (annotation domain tables land in batch 2 data model), with `dataset_versions`
  ([ADR-007](ADR-007.md)) recording which annotation batch a gold set came from.
- Recruitment planning (5+ annotators) is now an explicit product trigger, not an
  engineering whim.

## Rejected alternatives

- **Label Studio now:** rejected — premature without volume evidence (but pre-approved at trigger).
- **Argilla:** **REJECT** — feature freeze May 2025 verified; unmaintained trajectory.
- **doccano:** DEFER — viable MIT text-only fallback; not preferred (verify license/version
  at adoption time; currently unverified — secondary source).
- **Bespoke annotation UI in admin:** rejected for now — re-inventing task assignment,
  blind review, and IAA; revisit only if Label Studio integration proves inadequate.

## Migration implications

- Trigger work: deploy Label Studio (container #1 beyond optional Postgres) → define label
  schemas → invite annotators → export job (JSONL/CSV) → import into DB with provenance
  columns → quality rules validate imports ([ADR-005](ADR-005.md)).
- Everything stays additive: annotation tables are new domains in the data model (batch 2);
  existing gold files are seed/backfill inputs.
- Founder decision required on: annotator count, timeline, and whether annotation data
  leaves the host (privacy/sensitivity review).
