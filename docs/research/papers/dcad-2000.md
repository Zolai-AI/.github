## Abstract (condensed)

DCAD-2000 is a multilingual pre-training corpus covering **2,282 languages, 46.72 TB of text, 8.63 billion documents, and 155 writing systems**, built from newly extracted Common Crawl (CC-MAIN-2024-46) plus existing multilingual sources (MaLA, FineWeb, FineWeb-2). Its core contribution is methodological: instead of hand-tuned heuristic quality thresholds, it reframes data cleaning as an **anomaly detection** problem over eight statistical features — word count, character/word repetition ratios, special-character ratio, stopword ratio, flagged-word ratio, GlotLID language-ID confidence, and KenLM perplexity — so filtering adapts dynamically per corpus rather than per manual rule. Isolation Forest proved the most stable of the tested detectors (One-Class SVM, LOF, and K-Means were hyperparameter-sensitive). Models trained on DCAD-2000 beat raw/unfiltered baselines by roughly 5–20% normalized accuracy and threshold-based filtering by 3–10%, with the largest gains in low- and very-low-resource languages (up to +9.15 accuracy on SIB-200 vs FineWeb-2/New CC; also Glot500 and FLORES-200 gains).

## Takeaways for Zolai (PROPOSED adaptations)

| DCAD-2000 idea | Zolai application | Priority |
|----------------|-------------------|----------|
| Cleaning = anomaly detection, not fixed thresholds | Score web-scrape rows with the same 8 features + Isolation Forest instead of arguing over cutoffs | High |
| Cheap, language-agnostic features (LID score, perplexity, repetition) | Add a quality-score column to `zolai-datasets` cleaning so bad rows are flagged, not silently dropped | High |
| Isolation Forest > LOF/K-Means for stability | Our default detector choice if we implement this (fewer knobs, reproducible) | Medium |
| Statistical filter ≠ cultural filter | Run DCAD-style filter *alongside* ZVS-2018 forbidden-form rules — neither alone is sufficient | High |
| Report per-resource-tier gains, not one aggregate | Report Tedim vs Hakha/Falam/Paite quality metrics separately in audits | Medium |

**Non-goals:** DCAD-2000 trains LLMs on Common Crawl — our product stays RAG-first. Do not use this as justification for large-scale pre-training; use it as **cleaning-engineering** reference (same stance as FineWeb2).

## How it applies to our project

- **Data cleaning (KR1.5 / `zolai-datasets`):** concrete, implementable algorithm for the web-scrape staging path — currently our cleaning is rule/regex-based (HTML, mixed-language, `[a-z\-]` masks). Anomaly detection adds an adaptive layer that catches subtle noise rules miss.
- **Evaluation:** its benchmark suite (SIB-200, Glot500, FLORES-200) is the standard way cleaning claims get proven — we should analogously prove our cleaning with a small Tedim gold slice (pairs with IndigiEval notes).
- **RAG-first:** cleaner corpus ⇒ better retrieved context ⇒ fewer hallucinations; quality filtering upstream substitutes for the pre-training gains we intentionally forgo.
- **Citation:** closes UNKNOWN row #7 in the literature review with a primary NeurIPS source.

## Gaps vs Tedim

- KenLM perplexity requires per-language Wikipedia ≥10k clean sentences — Tedim almost certainly fails this, so we'd inherit DCAD's default (500) or substitute our own LM/n-gram scorer.
- 8 features are web-crawl oriented; Bible-parallel and dictionary rows need different quality signals (attestation counts, ZVS conformity).
- Anomaly detectors need a "normal" corpus to learn from — our clean-attested subset could serve as the reference population.
